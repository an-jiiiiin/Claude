# KNOW-ISH 자동화 런북

예약 작업이 하루 두 번 새 세션을 열고, 그 세션의 Claude가 이 문서를 그대로 따른다.
사람이 할 일은 **승인 한 번**뿐이다.

| 회차 | 실행 (KST) | 시리즈 | 게시 목표 |
|---|---|---|---|
| 오전 | 06:37 | `on` · **KNOW** 시사·경제·정치 (깊게) | 08:00 |
| 오후 | 16:37 | `off` · **-ISH** 마케팅·브랜드·트렌드 (가볍게) | 18:00 |

---

## 0. 준비
1. 저장소 `an-jiiiiin/Claude` 체크아웃 안의 `onoff/` 로 이동. 없으면 저장소를 추가하고 클론한다.
2. `npm install` (fonts) — `node_modules` 가 있으면 생략.
3. 오늘 날짜(KST)로 게시물 ID를 정한다: `YYYY-MM-DD-am` 또는 `YYYY-MM-DD-pm`.
   `posts/<id>/` 가 이미 있으면 새로 만들지 말고 그 게시물의 상태부터 확인한다.

## 1. 수집
- **WebSearch 로 지난 24시간 이슈**를 찾는다. 검색어는 여러 개를 같은 턴에 보낸다.
  - KNOW(오전): `오늘 경제 뉴스`, `금리 환율 증시 오늘`, `정부 정책 발표 오늘`, `국회 쟁점 오늘`, 해외 이슈 중 한국에 영향 큰 것
  - -ISH(오후): `마케팅 캠페인 화제`, `브랜드 콜라보 신제품 반응`, `성수 팝업`, `광고 바이럴`, `SNS 밈 트렌드`
  - 참고 매체: 연합뉴스, 한국경제, 매일경제, 한국은행·KDI(경제) / 아이보스, 오픈애즈, 매드타임스, 브랜드브리프(마케팅)
- 최근 `posts/` 7일치 주제와 겹치면 제외한다.

## 2. 주제 선정 (1개)
점수가 가장 높은 하나를 고른다.
- **화제성**: 여러 매체가 다루는가, 검색·SNS 반응이 있는가
- **"아는 척" 가치**: 회의·대화에서 써먹을 한 줄이 나오는가
- **근거**: 숫자와 사실을 1차 출처(기관 발표, 기업 공식 발표, 주요 언론)로 확인할 수 있는가
- **KNOW**: "왜"와 "나에게 미치는 영향"까지 설명 가능한가 / **-ISH**: 마케터가 가져갈 포인트가 있는가

## 3. 원고 — `posts/<id>/content.json`
형식은 `content/2026-11-19-am.json`(KNOW), `content/2026-11-19-pm.json`(-ISH)을 그대로 따른다.

- 구조: `cover` → 본문(`body` / `compare` / `points`) → `outro`
- 분량: KNOW **6~9장**, -ISH **5~7장** (인스타 API 최대 10장)
- 표지(`cover`): 스티커 8자 이내, 제목 2줄(최대 3줄), 핵심 단어 1개만 `==강조==`. 2EZ식 후킹.
- 본문: MOT·LUX식. 한 장에 한 메시지. 사진 있는 장 140자, 없는 장 260자 이내. 숫자·고유명사는 `**굵게**`, 핵심 문장은 `==형광펜==`.
- 마지막 `outro`: "한 줄 정리" — 아는 척할 때 쓸 문장.
- `caption`: 첫 줄 `[제목]`, 3~5줄 요약, 이미지·자료 출처, **해시태그는 정확히 5개**(브랜드/주제 핵심 3~4개 + 마지막 `#knowish`).
- `commentTags`: 첫 댓글에 달 **유입용(SEO) 태그 15~20개** 배열. 캡션 태그와 겹치지 않게.
  - 구성: 주제 세부 키워드 5~7개(브랜드·제품·인물·사건명) + 관련 검색어 4~6개(사람들이 실제 검색할 말, 예: `#카페신메뉴`, `#금리인상`) + 분야 고정 태그 5~7개
  - 분야 고정 태그 — KNOW: `#경제뉴스 #시사 #경제공부 #뉴스요약 #재테크 #카드뉴스 #시사상식` / -ISH: `#마케팅 #마케팅인사이트 #마케팅트렌드 #브랜딩 #마케터 #카드뉴스 #트렌드`
  - 너무 큰 태그(#일상, #좋아요 등)와 내용과 무관한 인기 태그는 쓰지 않는다.
- `sources`: 원고의 모든 숫자·주장을 뒷받침하는 링크.
- `ref`: 본문 장마다 출처 기관/매체명.

### 디자인 스타일 — 번갈아 쓰기
`content.json` 의 `"style"` 로 고른다. **같은 시리즈의 직전 게시물과 다른 스타일**을 쓴다(오전 KNOW끼리, 오후 -ISH끼리 번갈아). 직전 게시물에 style 이 없으면 classic 으로 본다. 사용자가 지정하면 그걸 따른다.

| style | 느낌 | 표지 | 본문에 쓰는 타입 |
|---|---|---|---|
| `classic` (기본) | 2EZ 썸네일 + MOT·LUX 본문. 정보형 | 사진 + 스티커 + 굵은 2줄 제목 (+ 가끔 말풍선) | body, gallery, compare, points (+ meme) |
| `mag` | 에디터 매거진 톤. 말 걸듯 가볍게, 밈 감성 | `vol. NNN` · `editor_ 노이쉬` 라벨, ■ 태그, 얇은 큰 제목, 스티커 없음 | **letter**(파스텔 바탕 에디터 노트), **meme**(사진 2~3칸 + 말풍선), gallery, body, points |

- mag 표지: `tag`(태그 한 단어), 제목 30자 이내. vol 번호는 posts 순서로 자동.
- mag 게시물이라도 표지만 classic 썸네일(스티커 + 굵은 제목)로 쓰려면 cover 에 `"style": "classic"` 과 `sticker` 를 넣는다.
- `letter`: `label`(예: "에디터의 팝업 노트"), `title`, `text`(사진 있으면 200자, 없으면 330자), 선택 `image` + `say`(사진 옆 말풍선 한 줄).
- `meme`: `title`(검은 띠 제목), `panels` 2~3칸 — 각 칸 `image`, `say`(상황), `react`(→ 반응, `==강조==`는 시리즈 진한색), `side`(l/r).
- meme 사진도 라이선스 규칙 그대로. 출처 불명 밈 짤(핀터레스트 등)은 쓰지 않는다 — 보도자료·공식 이미지·라이선스 스톡·AI 생성 이미지만.
- 예시: `content/demo/mag-ganadi.json` → `samples/mag-demo/`

### 말풍선 · 사진 많이 쓰기 (두 스타일 공통)
- **말풍선(`says`)** — 게시물 성격에 맞을 때 **가끔** 쓴다(가벼운 -ISH, 반응이 재밌는 이슈 위주. 심각한 시사·사건 이슈엔 쓰지 않는다).
  - 표지(`cover`)나 사진 있는 `body` 에 `"says": [{"text": "너 어느 기숙사야?", "x": 8, "y": 36, "rot": -3}]` — x·y 는 % 위치, 최대 2개, 한 줄 24자 이내.
  - 패턴: 상황 한 마디 → `→ 반응` 한 마디. `==강조==` 는 시리즈 진한색.
  - 사진 속 중요한 부분(얼굴·제품·글자)을 가리지 않게 위치를 잡고 review.png 로 확인.
- **사진 많이**: 실사 자료가 있는 장을 **전체의 절반 이상**으로. 한 이슈에 보도자료·공식 이미지를 여러 장 모은다.
  - `gallery`: 사진 2~4장 한 장에 — `images: [{src, credit, license, pos, label, says}]`, 설명 120자 이내, `ref` 필수. 3장이면 왼쪽 큰 사진 + 오른쪽 2장.
  - `meme`(사진 2~3칸 + 말풍선)도 classic 에서 써도 된다.
- 예시: `content/demo/classic-say-gongcha.json` → `samples/classic-say-demo/`

### 사실·톤 규칙 (반드시)
- 모든 숫자·날짜·인용은 sources 에서 확인한 것만 쓴다. 확인 못 한 건 빼거나 "~로 알려졌다"가 아니라 **아예 쓰지 않는다**.
- **정치 이슈는 중립**: 쟁점이면 양쪽 입장을 같은 분량으로(`compare` 활용). 특정 정당·인물에 대한 평가·조롱 금지.
- 투자 권유 금지("사세요/파세요" X). "확인해보세요" 수준까지만.
- 사건·사고 피해자, 미성년자, 사생활 이슈는 다루지 않는다.
- -ISH 는 가볍게, 하지만 브랜드·인물 비하 금지.

## 4. 이미지 — `posts/<id>/images/`
실사 사진은 **라이선스가 확인된 것만** 쓴다. 출처만 적는다고 써도 되는 게 아니다.

| 우선순위 | 소스 | 비고 |
|---|---|---|
| 1 | 정책브리핑 korea.kr 사진 (공공누리 제1유형) | 정부·정책·경제 이슈. credit `대한민국 정책브리핑`, license `공공누리 제1유형` |
| 2 | 기업 공식 보도자료·뉴스룸 사진 | 해당 브랜드 사례일 때. 기사에 `<기업명> 제공`으로 실린 보도자료 사진은 기사 URL로 받아도 됨(og:image). credit `<기업명> 제공`, license `보도자료` |
| 3 | Wikimedia Commons (CC BY / CC BY-SA / PD) | 건물·인물·장소. credit 에 저작자, license 에 라이선스명 |
| 4 | Unsplash | 일반 이미지(돈, 도시, 사무실 등). credit `Unsplash / 작가명`, license `Unsplash License` |

- 언론사(연합뉴스 등) 사진은 **쓰지 않는다** — 유료 라이선스.
- 내려받기: `node src/fetch-image.mjs <이미지 또는 페이지 URL> posts/<id>/images/01` (프록시 환경이면 스크립트가 알아서 프록시로 다시 실행)
- 사진에 원래 들어 있는 글자가 스티커·제목과 겹치면 다른 사진을 쓰거나 `image.pos`(예: `"center 70%"`)로 위치를 옮긴다. 포스터형 이미지는 `"fit": "contain"` 도 가능.
- `content.json` 의 해당 슬라이드 `image` 에 `src`(저장 경로, onoff/ 기준), `credit`, `license` 를 채운다.
- 이모지·일러스트가 필요한 자리(주로 -ISH)는 AI 생성 이미지 가능 — license `AI 생성`.
- 이미지를 못 구하면 `src` 를 비워 두고(회색 자리) 검수 요청 때 알린다. 가짜·무단 이미지로 채우지 않는다.

## 5. 빌드
```bash
node src/build.mjs posts/<id>
```
- `slides/01.png …`, `review.png`, `review.md`, `status.json(state: pending_review)` 이 생긴다.
- 출력의 `problems` 가 비어 있지 않으면 원고를 고치고 다시 빌드한다(이미지 미지정은 예외).
- `review.png` 를 직접 열어 보고, 글자 넘침·겹침·오타가 있으면 고친다.

## 6. 저장 & 승인 요청
1. 이 세션의 작업 브랜치에 `onoff/posts/<id>/` 를 커밋하고 push 한다.
2. 사용자에게 `review.png`, 표지(`slides/01.png`)를 보내고(SendUserFile, status `proactive`), 푸시 알림을 보낸다.
3. 메시지: 주제 한 줄, 왜 골랐는지 한 줄, 확인이 필요한 점(이미지 미지정, 애매한 수치 등). 끝에 **"승인 / 수정할 내용"** 을 묻는다.
4. **승인 전에는 절대 게시하지 않는다.**

## 7. 승인 후 게시
- 수정 요청 → 원고 수정 → 5~6단계 반복.
- "승인" →
  1. `status.json` 의 state 를 `approved` 로 바꾸고 커밋·push (이미지 공개 URL 필요).
  2. `node src/publish.mjs posts/<id> --dry-run` 으로 URL·캡션 확인.
  3. `node src/publish.mjs posts/<id>` 실행.
  4. 결과(permalink)를 커밋·push 하고 사용자에게 알린다.
- 게시에 필요한 설정이 아직 없으면(아래) 게시는 건너뛰고, 사용자에게 **수동 업로드용 파일**(slides/01~NN.png + caption.txt + comment.txt)을 보내고, 게시 직후 comment.txt 를 첫 댓글로 달라고 안내한다.

## 게시에 필요한 설정 (최초 1회)
- `docs/INSTAGRAM_SETUP.md` 를 따라 비즈니스 계정·토큰·`IG_USER_ID` 준비
- 클라우드 환경 네트워크에 `graph.facebook.com` 허용 + 토큰을 네트워크 시크릿으로 저장
- 이미지 수집용 허용 호스트: `www.korea.kr`, `upload.wikimedia.org`, `commons.wikimedia.org`, `images.unsplash.com` 등
