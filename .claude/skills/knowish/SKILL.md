# KNOW-ISH 요청형 카드뉴스

정기 회차(오전 KNOW / 오후 -ISH)와 별개로, 사용자가 원하는 주제를 **원할 때** 만든다.
작업 방식과 규칙은 정기 회차와 같다: `onoff/AUTOMATION.md` 를 먼저 끝까지 읽고 그 규칙(사실·톤, 이미지 라이선스, 원고 형식, 태그, 빌드, 승인)을 그대로 지킨다. 아래는 요청형에서 달라지는 점만 적는다.

## 0. 준비
- 작업 폴더: 저장소 루트의 `onoff/`. `node_modules` 가 없으면 `npm install`.
- 이 파일이 있는 브랜치가 `onoff/` 의 최신 상태다. 게시물은 이 세션의 작업 브랜치에 커밋·push 한다.

## 1. 요청 해석 (묻지 말고 정한다)
사용자 요청(인자)에서 아래를 뽑고, 빠진 건 기본값으로 정한 뒤 바로 진행한다. 정말 주제를 알 수 없을 때만 한 번 묻는다.

| 항목 | 기본값 |
|---|---|
| 주제 | 필수. 링크를 주면 그 기사/페이지가 출발점 |
| 시리즈 | 시사·경제·정치·정책·사회 → `on`(KNOW, 하늘). 마케팅·브랜드·캠페인·트렌드·밈·팝업 → `off`(-ISH, 마젠타). 애매하면 깊이로 판단: "왜/영향" 설명이 핵심이면 KNOW |
| 장수 | KNOW 7장, -ISH 6장 (요청 시 KNOW 6~9, -ISH 5~7 안에서) |
| 톤 | 시리즈 기본 톤. 사용자가 원하는 톤("더 가볍게", "숫자 위주", "비교 위주")이 있으면 반영 |
| 스타일 | 본문(2장~)만 해당. 같은 시리즈 직전 게시물과 다른 것(`classic` ↔ `mag`). 사용자가 "매거진 톤", "밈 스타일", "정보형" 등으로 말하면 그대로. 자세한 건 런북 '디자인 스타일' |
| 게시물 ID | `YYYY-MM-DD-req-<영문슬러그>` (KST 날짜, 예: `2026-11-20-req-gongcha-hp`) |

## 2. 리서치 (정기 회차보다 깊게)
- WebSearch 를 여러 갈래로 **한 턴에** 보낸다: 사실관계, 숫자, 배경/맥락, 반응·논쟁, 비교 사례.
- 핵심 기사·공식 발표는 WebFetch 로 직접 읽어 숫자와 날짜를 확인한다. 매체마다 다르면 다수·1차 출처를 따르고 승인 요청 때 알린다.
- KNOW: "그래서 나한테 뭐가 달라지나"까지. 정치·사회 쟁점은 양쪽 입장을 같은 분량으로.
- -ISH: 마케터가 가져갈 포인트 3가지를 반드시 뽑는다.

## 3. 만들기
1. `onoff/posts/<id>/content.json` 작성 — 형식은 `onoff/content/2026-11-19-am.json`(KNOW), `onoff/posts/2026-11-19-pm/content.json`(-ISH) 참고. `caption`(해시태그 정확히 5개, 마지막 `#knowish`), `commentTags`(유입용 15~20개), `sources` 필수.
2. 사진: 런북의 이미지 규칙대로. **사진 있는 장이 절반 이상**이 되게 여러 장 모으고(`gallery` 활용), 가벼운 주제면 본문 사진에 말풍선(`says`)을 가끔 얹는다. **표지(썸네일)는 항상 고정 틀**이고, 변형은 사실 기반 어그로 칩(`chips`)만 쓴다(런북 '썸네일 고정'). 기사에 "<기업명> 제공"으로 실린 보도자료 사진은 `node src/fetch-image.mjs <기사 URL> posts/<id>/images/01` 로 받는다. 받은 사진은 직접 열어 보고 고른다(사진 속 글자가 스티커·제목과 겹치면 다른 사진 또는 `image.pos`).
3. `node src/build.mjs posts/<id>` → `problems` 0개가 될 때까지 고친다.
4. `review.png` 와 슬라이드를 직접 보고 글자 넘침·겹침·오타를 고친다.

## 4. 승인 요청
- 커밋·push 후 `review.png` 와 표지(`slides/01.png`)를 보낸다.
- 메시지: 주제 한 줄, 선택한 시리즈와 이유, 각 장 요약(한 줄씩), 확인이 필요한 점(매체 간 다른 수치, 사진 미지정 등), 끝에 "승인 / 수정할 내용".
- **승인 전에는 게시하지 않는다.**

## 5. 수정 · 승인 후
- 수정 요청 → 원고 수정 → 재빌드 → 다시 보여준다. (재빌드하면 상태가 `pending_review` 로 돌아간다)
- "승인" → `status.json` state `approved` → 커밋·push →
  - 인스타 API 가 설정돼 있으면 `node src/publish.mjs posts/<id> --dry-run` 확인 후 게시(첫 댓글 태그 포함).
  - 없으면 업로드 패키지(slides/01~NN.png, caption.txt, comment.txt)를 보내고 순서·4:5 비율·첫 댓글 안내.
- 사용자가 게시 시각을 정해 달라고 하면 정기 회차(08:00 / 18:00)와 겹치지 않게 추천한다 (예: 12:30 점심, 21:00 저녁).
